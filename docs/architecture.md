# 系统架构设计

QuizDock 是一款现代化、本地优先（Local-First）的刷题系统。整体架构围绕“**执行引擎与题库内容彻底解耦**”和“**单文件极简交付**”两大原则设计。

## 架构概览

系统由 Go 构建的高性能后端服务与 React/TypeScript 单页前端（SPA）组成，数据持久化依托单文件 SQLite：

```text
┌────────────────────────────────────────────────────────┐
│               Web 前端 (React + TypeScript)             │
│   练习交互 / 题目排版 / 会话恢复 / 错题管理 / 官方题库  │
└───────────────────────────┬────────────────────────────┘
                            │ HTTP API (RESTful / JSON + gzip)
┌───────────────────────────▼────────────────────────────┐
│                    Go HTTP 服务内核                    │
│  ├── 访问控制 (Auth & Session Cookie)                   │
│  ├── 题库引擎 (.qbank 校验、解压检查与事务导入)         │
│  ├── 练习逻辑 (顺序/随机/错题专练/进度统计)             │
│  ├── 在线生态 (官方版本与题库更新发现)                 │
│  ├── 静态资源内嵌 (embed.FS WebUI)                     │
│  └── 数据访问层 (SQLite Driver & Schema Migration)     │
└───────────────────────────┬────────────────────────────┘
                            ▼
               本地存储 (SQLite 数据库文件)
```

## 核心模块职责

- **`cmd/quizdock`**：CLI 命令行解析、子命令分发、环境配置与进程生命周期管理。
- **`internal/api`**：RESTful API 路由分发、基于 Cookie 的会话认证拦截、更新代理与内嵌 Web 静态资源托管。
- **`internal/qbank`**：标准 `.qbank` 归档包的解析、路径穿越与格式合规校验、SHA-256 校验和计算及打包构建。
- **`internal/database`**：SQLite 数据库连接管理、有序递增的数据迁移执行（Migration）、题库元数据与用户学习状态的 CRUD 封装。
- **`internal/releases`**：GitHub Release 接口适配，支持应用核心与官方题库双轨独立更新检测。
- **`web`**：现代化响应式前端单页应用，负责交互逻辑、Markdown 富文本渲染及可恢复练习会话流转。

## 关键设计机制

### 1. 题库与学习状态解耦存储

系统在数据库设计上严格贯彻“资源定义”与“用户状态”解耦：
- **资源表**：记录题库清单、章节元信息、题目内容及选项定义。
- **状态表**：独立记录用户做题历史（`attempts`）、练习进度（`study_progress`）、错题掌握度（`question_mastery`）、收藏状态（`question_state`）与练习偏好（`app_settings`）。

题目由 `bank_id + question_id` 复合主键唯一定位。无论是题库升级还是卸载重装，系统均通过原子事务保证用户既有的答题进度与错题记录完好保留。

### 2. 多级状态协同与页面无感恢复

为保障用户在刷题过程中随时刷新、关闭或跳转后能无缝恢复会话，QuizDock 采用了三级状态协同机制：
1. **URL 路由状态**：当前练习模式与题目定位直接体现于路由（如 `/practice/:mode/:uid`），筛选维度编码至 URL 查询参数，保证链接可直达。
2. **短期会话缓存 (`sessionStorage`)**：维护当前练习队列及滚动上下文，确保刷新页面后题目顺序（特别是随机模式）与阅读位置不丢失。
3. **长期数据持久化 (SQLite)**：提交答案和设置变更即时写入本地数据库，答题记录、错题标记及自动提交等练习偏好持久留存。

### 3. 安全与网络部署模型

- **网络监听**：服务默认仅绑定本地回环地址 `127.0.0.1`，避免未经授权的网络暴露。
- **身份认证**：支持可选的账户密码认证。设置密码后，除健康检查和认证端点外的业务接口均受 `HttpOnly` 会话保护。
- **生产反向代理**：建议生产环境前置标准反向代理（如 Nginx、Caddy 或 Traefik）统一管理 SSL/TLS 证书及外部网络访问。

### 4. 练习链路性能模型

- **合并初始化**：`/api/v1/bootstrap` 在一次请求中返回认证状态和授权范围内的应用元数据，避免首屏串行往返。
- **精简启动数据**：练习启动接口只返回轻量题目队列、当前题和恢复位置，队列不会携带题目正文。
- **滑动预取窗口**：前端批量预取后续 5 道题及其本地图片，以容量受限的内存缓存承接顺序切题；失败时自动回退到单题请求。
- **批量数据访问**：多题详情通过固定的题目、Tag、题目组成三组 SQL 查询加载，避免随小题数增长的 N+1 查询。
- **渲染与持久化限流**：题号窗分页渲染，Markdown 解析结果按稳定输入复用；进度写入合并短时间内的连续切题，并在页面退出前刷新。
